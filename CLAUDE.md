# Brandon Church · portfolio

## Start here, every session

1. Read `BRIEF.md`. It is the only source of rules.
2. Read `PLAN.md`. It says what is done and what is next.
3. After a compaction, read both again before doing anything.

## Rules for working here

- If something is not in `BRIEF.md`, it is not a rule. Do not invent one, and do not carry one over from the second build.
- When Brandon makes a ruling, write it into `BRIEF.md` straight away, with the date. Move items between Settled, Open and Dropped as he decides them.
- Only Brandon ticks a box in `PLAN.md`. Update its "Now" section whenever the state changes.
- Never show him something with "the final will be better". If it is not at the bar, keep working or say plainly what is wrong with it.
- Tell him exactly what he is and is not approving each time you show him something.
- Give him lists, not paragraphs. End every message with a clear, simple recommendation.
- Fable does the creative work itself. Any subagent runs on Opus.
- Look at what you build. Take real screenshots and filmstrips and open them before showing him anything.
- Commit and push after each piece of work so every chat sees the same repo.

## Writing and code

- No em dashes in anything the site shows or in these documents. Use a period, a comma or an interpunct (·).
- Almost no code comments. Keep one only when it explains a reason someone could otherwise undo.
- He rewrites the site's copy himself. Draft copy only when he asks.
